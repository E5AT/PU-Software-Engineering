Тема 10 от Конспекта

Структура Дърво и Двоични дървета

Дървото (Tree) е йерархична структура от данни, състояща се от върхове (Nodes), свързани помежду си с ребра (Edges). Всеки връх има нула или повече наследници (деца), а самият корен (Root) няма родител. Върховете без наследници се наричат листа (Leaves).

Двоично дърво (Binary Tree) е дърво, в което всеки връх може да има най-много две деца – обикновено наричани ляво дете (Left child) и дясна дете (Right child).

Реализация на възел (Node) в C#

Според логиката в книгата на проф. Голев и материалите на Microsoft Learn, двоичното дърво се изгражда динамично в Heap паметта чрез референции (указатели) към обекти от следния тип:

public class TreeNode 
{
    public int Value;           // Стойност на върха
    public TreeNode Left;       // Указател към лявото поддърво
    public TreeNode Right;      // Указател към дясното поддърво

    public TreeNode(int value) 
    {
        this.Value = value;
        this.Left = null;
        this.Right = null;
    }
}
Рекурсивни алгоритми

Обхождане на Двоично дърво

Обхождането означава да посветим всеки връх в дървото точно веднъж. Тъй като структурата е рекурсивна, обхожданията се пишат изключително елегантно чрез рекурсия. Различаваме три основни вида в зависимост от това кога обработваме текущия корен (Root):

1. Preorder (Корен - Ляво - Дясно): Първо се обработва корена, след това лявото поддърво и накрая дясното.
2. Inorder (Ляво - Корен - Дясно): Първо се изчиства изцяло лявото поддърво, после се обработва корена, и тогава дясното.
3. Postorder (Ляво - Дясно - Корен): Първо се обхождат децата (ляво, после дясно), а самият корен се обработва най-накрая.

C# Реализация на трите обхождания

// 1. PREORDER
public void PreorderTraversal(TreeNode root) 
{
    if (root == null) return; // Дъно на рекурсията
    Console.Write(root.Value + " "); // ОБРАБОТКА НА КОРЕНА
    PreorderTraversal(root.Left);     // ЛЯВО
    PreorderTraversal(root.Right);    // ДЯСНО
}

// 2. INORDER
public void InorderTraversal(TreeNode root) 
{
    if (root == null) return;
    InorderTraversal(root.Left);      // ЛЯВО
    Console.Write(root.Value + " "); // ОБРАБОТКА НА КОРЕНА
    InorderTraversal(root.Right);     // ДЯСНО
}

// 3. POSTORDER
public void PostorderTraversal(TreeNode root) 
{
    if (root == null) return;
    PostorderTraversal(root.Left);     // ЛЯВО
    PostorderTraversal(root.Right);    // ДЯСНО
    Console.Write(root.Value + " ");  // ОБРАБОТКА НА КОРЕНА
}
Тема 11 от Конспекта

Двоични дървета за търсене (BST)

Двоично дърво за търсене (Binary Search Tree - BST) е специализирано двоично дърво, което налага строга наредба на елементите си за постигане на максимално бърза обработка:

Свойство на BST: За всеки един възел в дървото важи: всички стойности в неговото ляво поддърво са строго по-малки от неговата собствена стойност, а всички стойности в неговото дясно поддърво са по-големи от него.

Основни операции

1. Търсене (Search / Contains)

Започваме от корена. Ако търсената стойност е по-малка от текущата, рекурсивно отиваме само вляво. Ако е по-голяма – отиваме само вдясно. Така на всяка стъпка отсичаме половината от оставащото дърво, постигайки логаритмична сложност.

2. Включване (Insert)

Подобно на търсенето, се спускаме по дървото докато достигнем празна референция (null), където заделяме новия възел като нов лист, запазвайки правилата на структурата.

C# Реализация на Търсене и Вмъкване

// Проверка дали стойност съществува в BST
public bool Contains(TreeNode root, int value) 
{
    if (root == null) return false;
    if (value == root.Value) return true;
    
    if (value < root.Value)
        return Contains(root.Left, value); // Търсим наляво
    else
        return Contains(root.Right, value); // Търсим надясно
}

// Рекурсивно вмъкване на елемент
public TreeNode Insert(TreeNode root, int value) 
{
    // Намерено е правилното празно място, заделяме възела в паметта
    if (root == null) 
        return new TreeNode(value); 

    if (value < root.Value)
        root.Left = Insert(root.Left, value);
    else if (value > root.Value)
        root.Right = Insert(root.Right, value);

    return root; // Връщаме структурата
}
⚠️ Сложност по Big-O (Важно за устния изпит!):
- Среден случай (Балансирано дърво): Търсене, Вмъкване и Изтриване се изпълняват за O(log n) време, тъй като височината съответства на логаритъм от броя елементи.
- Най-лош случай (Дегенерирало дърво): Ако подадем числата предварително сортирани (напр. 1, 2, 3, 4, 5), дървото се разклонява само надясно и се превръща в линеен списък. Тогава сложността скача до O(n)!

Интерактивна тренировка

Отговори на следните въпроси наум, преди да щракнеш върху тях, за да симулираш устния изпит.

ВЪПРОС 1 — СВОЙСТВО НА INORDER
Защо ако изпълним INORDER обхождане върху едно Двоично дърво за търсене (BST), резултатът винаги излиза перфектно сортиран във възходящ ред?
👆 Кликни за отговор
Това е директно следствие от дефиницията на BST и схемата на Inorder.

Inorder работи по схемата: Ляво -> Корен -> Дясно. Тъй като в BST всички по-малки стойности са заложени по дефиниция в лявото поддърво, а по-големите в дясното, алгоритъмът гарантирано извежда първо най-малките елементи отляво, после средния елемент (корена) и накрая големите отдясно. Рекурсията пренася това свойство на всяко ниво.
ВЪПРОС 2 — ДЕГЕНЕРИРАНЕ
Какво представлява "дегенерирало дърво" и как се променя Big-O сложността на операциите при него?
👆 Кликни за отговор
Дегенерирало дърво (Degenerate tree) възниква, когато всеки родителски възел има само по едно дете. Дървото губи своите разклонения и се превръща в линеен свързан списък.

Това се случва, когато вмъкваме в празно BST елементи, които са вече сортирани (например: 10, 20, 30, 40). Височината на дървото става равна на n, а сложността за търсене деградира от бързото константно-подобно O(log n) до бавното линейно обхождане O(n).
ВЪПРОС 3 — СИМУЛАЦИЯ НА ОБХОЖДАНЕ
Имаме двоично дърво с корен 10, ляво дете 5 и дясно дете 15. Ако на конзолата се отпечата поредицата "10 5 15", кое обхождане е задействано?
👆 Кликни за отговор
Използвано е Preorder обхождане.

Обяснение: Схемата на Preorder е Корен -> Ляво -> Дясно. Виждаме, че коренът (10) е обработен и отпечатан веднага в самото начало, последван от лявото дете (5) и дясното дете (15). При Inorder щеше да бъде "5 10 15", а при Postorder — "5 15 10".
