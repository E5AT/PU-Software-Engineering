Тема 1 от Конспекта

Стандартни типове данни в C#

Типовете данни в C# се делят на две основни категории, които определят къде се съхраняват в паметта: Стойностни (Value Types) и Референтни (Reference Types).

Стойностни (Stack): Съхраняват самата стойност. Примери: int, float, double, bool, char, структури (struct).

Референтни (Heap): Съхраняват указател (адрес) към данните в динамичната памет. Примери: масиви, string, класове, object.

Специфики, важни за изпита:

Тип Бинове / Точност Суфикс в кода
float 32-битов (7 знака точност) f (напр. 3.14f)
double 64-битов (15-16 знака точност) Няма (по подразбиране)
decimal 128-битов (28-29 знака - за финанси) m (напр. 10.50m)
long 64-битов цяло число L (напр. 9223...L)
Тема 1 от Конспекта

Масиви в C#

Масивът е съвкупност от променливи от един и същи тип, разположени в контигуална (непрекъсната) памет. Масивите в C# са референтни типове, следователно самите елементи живеят в Heap-а.

1. Двумерни масиви (Матрици)

Правоъгълна таблица. Заделя се като един непрекъснат блок в паметта.

int[,] matrix = new int[3, 4]; // 3 реда, 4 колони

for (int row = 0; row < matrix.GetLength(0); row++) 
{
    for (int col = 0; col < matrix.GetLength(1); col++) 
    {
        Console.Write(matrix[row, col] + " ");
    }
}
⚠️ Внимание: За матрици ВИНАГИ използвай .GetLength(0) и .GetLength(1). Ако напишеш само .Length, ще ти върне общия брой елементи (в случая 12) и ще счупи цикъла!

2. Назъбени масиви (Jagged Arrays)

Масив от масиви. Всеки ред е отделен обект в Heap-а и може да има различна дължина.

int[][] jagged = new int[3][];
jagged[0] = new int[2] { 1, 2 };       // Ред с 2 елемента
jagged[1] = new int[4] { 3, 4, 5, 6 }; // Ред с 4 елемента

for (int i = 0; i < jagged.Length; i++) 
{
    for (int j = 0; j < jagged[i].Length; j++) // Всеки ред си има собствен Length!
    {
        Console.Write(jagged[i][j] + " ");
    }
}
Тема 7 от Конспекта

Линеен списък. Реализация в .NET

Когато размерът на данните не е известен предварително, масивите стават неудобни, защото са с фиксирана дължина. Тук на помощ идват линейните списъци.

List<T> (Динамичен масив)

Реализиран е чрез вътрешен масив (в паметта стои контигуално). Когато капацитетът му се запълни, той създава нов масив с двойно по-голям размер и копира старите елементи.

  • Достъп по индекс: Бърз O(1)
  • Вмъкване накрая: Бързо O(1) амортизирано
  • Вмъкване в началото/средата: Бавно O(n), защото трябва да отмести всички елементи надясно.

LinkedList<T> (Двойно свързан списък)

Реализиран чрез възли (Nodes). Всеки възел пази своята стойност и указатели към следващия и предишния възел. Разпръснати са из паметта (не са контигуални).

  • Достъп по индекс: Няма! Трябва да обходиш списъка O(n).
  • Вмъкване в началото/накрая: Много бързо O(1).
  • Вмъкване в средата (ако знаеш възела): Бързо O(1), просто пренасочваш указателите.
💡 Изпитен въпрос: Коя структура ще изберете, ако приложението ви постоянно добавя и трие елементи от началото на списъка?
Отговор: LinkedList<T>, защото добавянето в началото е O(1). При List<T> ще е O(n) заради пренареждането на целия масив.

Интерактивна тренировка

Опитай да отговориш наум или на лист, преди да разкриеш отговора. Тези въпроси симулират устни или писмени изпитни задания.

ВЪПРОС 1 — ГРЕШКА В КОДА
Какво ще се случи, ако изпълним следния код? Защо?

int[] arr = new int[5];
int last = arr[5];
👆 Кликни за отговор
Ще се хвърли изключение System.IndexOutOfRangeException.

Причина: Масивите се индексират от 0. Масив с размер 5 има индекси 0, 1, 2, 3, 4. Опитът да се достъпи arr[5] излиза извън границите на заделената памет.
ВЪПРОС 2 — СРАВНЕНИЕ НА СЛОЖНОСТ
Трябва да търсим специфичен елемент (по стойност) в несортирана колекция. Каква е времевата сложност (Big-O) за търсене в List<T> спрямо LinkedList<T>?
👆 Кликни за отговор
И в двата случая сложността е O(n) (Линейно време).

Тъй като колекцията не е сортирана, единственият начин да намерим елемента е чрез последователно обхождане от началото до края (Linear Search), независимо дали данните са в масив (при List) или във възли (при LinkedList).
