Ден 6: Обхождане с връщане назад

Днес навлизаме в Backtracking (Връщане назад) – една от най-елегантните рекурсивни техники. Тя се използва, когато искаме да намерим едно или всички решения на задача, но пространството от възможни варианти е твърде голямо за груба сила (Brute Force).

🎯 Фокус за изпита: Проф. Голев иска да види дали разбираш точно кога алгоритъмът "отстъпва". Ключовият момент в кода не е рекурсивното извикване, а възстановяването на състоянието след него!

Какво покриваме днес:

  • Тема 6: Теоретична същност на метода Backtracking (Глава 4 от помагалото).
  • Пример 1: Път в лабиринт (класическа задача с маркиране и отмаркиране).
  • Пример 2: Задачата за дамите / Разходка на коня. Комбинаторен взрив.
Тема 6 от Конспекта

Същност на метода Backtracking

Според проф. Голев, обхождането с връщане назад се дефинира като метод, при който решението се конструира последователно. Методът разчита на системния стек (чрез рекурсия), за да пази състоянието на частичното решение.

Основни принципи:

  1. Последователно изграждане: На всяка стъпка правим опит да добавим нов елемент към текущото частично решение така, че то да отговаря на правилата.
  2. Продължаване при успех: Ако добавянето е валидно (напр. стъпваме на свободна клетка), извикваме рекурсията за следващата стъпка.
  3. Връщане назад (Backtrack): Когато стигнем до "задънена улица" (нито един ход не е валиден), се връщаме на предходната стъпка. За да пробваме друга алтернатива, задължително трябва да отменим (размаркираме) последното си действие!
Пример 1

Намиране на път в лабиринт

Търсим път от стартова позиция до изхода ('е'). Движим се в 4 посоки. Клетките могат да бъдат свободни (' '), стени ('*') или вече посетени ('s').

C# Реализация

Обърни специално внимание на последните редове във втория if. Това е сърцето на алгоритъма!

static void FindPath(int row, int col, char direction) 
{
    // 1. Дъно: Проверка за излизане извън границите на матрицата
    if (col < 0 || row < 0 || col >= lab.GetLength(1) || row >= lab.GetLength(0)) 
        return; 

    path[position++] = direction; // Записваме посоката

    // 2. Дъно: Проверка за изход
    if (lab[row, col] == 'е') 
    {
        PrintPath(path, 1, position - 1);
    }
    
    // 3. Опит за продължаване, само ако клетката е свободна
    if (lab[row, col] == ' ') 
    {
        lab[row, col] = 's'; // МАРКИРАМЕ като посетена

        FindPath(row, col - 1, 'L'); // ляво
        FindPath(row - 1, col, 'U'); // нагоре
        FindPath(row, col + 1, 'R'); // надясно
        FindPath(row + 1, col, 'D'); // надолу

        // ВРЪЩАНЕ НАЗАД (BACKTRACK)
        // Ако нито един път не е успял, възстановяваме клетката,
        // за да може да се мине през нея по друг маршрут!
        lab[row, col] = ' '; 
    }
    position--; // Трием текущата стъпка от пътя
}
Пример 2

Разходка на коня / Задача за дамите

Проф. Голев използва "Разходка на коня" като еквивалент на "Задачата за 8-те дами". Логиката е абсолютно същата: опитваме всички възможни ходове, и ако задълпомним – отстъпваме.

Концептуален C# код (по проф. Голев)

public bool Solve(int x, int y, int currentStep) 
{
    visited[x, y] = currentStep; // 1. Маркираме текущата позиция

    if (AllNodesVisited()) 
        return true; // Успех! Всички фигури са поставени

    // Опитваме всички възможни ходове от масиви с отмествания (offsets)
    for (int i = 0; i < offsetX.Length; i++) 
    {
        int newX = x + offsetX[i];
        int newY = y + offsetY[i];

        if (IsSafe(newX, newY)) // Ако позицията е валидна
        {
            // Рекурсивно влизаме напред
            if (Solve(newX, newY, currentStep + 1)) 
                return true; 
        }
    }

    // 2. ВРЪЩАНЕ НАЗАД (BACKTRACK)
    // Щом цикълът е приключил и не сме върнали true, значи сме блокирани.
    visited[x, y] = 0; 
    
    return false; // Връщаме неуспех към предишното извикване
}
Ефективност: За 8-те дами възможните комбинации са 8⁸ (огромен брой). Brute force би генерирал всичките. Backtracking генерира само валидните частични решения и отрязва цели "клони" от дървото на решенията веднага щом 2 дами се засекат. Въпреки това сложността остава експоненциална.
Проверка на знанията

Интерактивна тренировка

ВЪПРОС 1 — РАЗПОЗНАВАНЕ НА МЕТОДА
Кой е единственият ред код в алгоритъма за лабиринта, който го превръща от обикновено търсене в дълбочина (DFS) в истински "Backtracking"?
👆 Кликни за отговор
Редът: lab[row, col] = ' ';

Ако просто маркираме клетките със 's' (посетени), ние ще намерим един път (DFS). Но възстановявайки клетката обратно на свободна (интервал), ние позволяваме на алгоритъма да открие всички възможни пътища, преизползвайки същата клетка за други маршрути.
ВЪПРОС 2 — ПАМЕТ И ПРЕПЪЛВАНЕ
Сложността по време на Backtracking за Задачата за дамите е огромна (експоненциална). Означава ли това, че алгоритъмът е опасен за паметта (StackOverflow) при нормална шахматна дъска (8x8)?
👆 Кликни за отговор
Не. Паметта (дълбочината на рекурсията) зависи само от броя на стъпките, не от броя на генерираните клони. За 8x8 дъска, рекурсията ще достигне максимална дълбочина от 8 извиквания (по едно за всяка дама). Системният стек се справя с това без никакъв проблем.

Проблемът е времето за процесора, не паметта.
ВЪПРОС 3 — УСЛОВИЕ ЗА "ДЪНО"
В кода на проф. Голев за Разходка на коня се извиква метода IsSafe(newX, newY). Какво типично трябва да проверява този метод?
👆 Кликни за отговор
Той трябва да провери две основни неща:
1. Дали новите координати (newX, newY) не излизат извън границите на дъската (напр. масив 8x8).
2. Дали клетката вече не е била посетена в текущия път (напр. visited[newX, newY] == 0).
