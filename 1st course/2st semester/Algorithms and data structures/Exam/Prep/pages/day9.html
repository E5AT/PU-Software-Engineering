Ден 9: Сложни алгоритми върху графи

Поздравления! Достигна до последния и най-комплексен модул от твоята подготовка. Днес ще разгледаме трите "тежки" алгоритъма за работа с графи, които изискват обединяване на знанията ти за масиви, матрици, рекурсия и структури от данни.

🎯 Фокус за изпита (Теми 14, 15 и 16): Тези теми са "черешката на тортата". Професорите очакват да разбираш идеята за "релаксация" (Дейкстра), същността на "лакомите алгоритми" (MST) и защо Топологичната сортировка работи само при графове без цикли (DAG).

Какво покриваме днес:

  • Тема 15: Минимално покриващо дърво (MST) чрез Лакоми алгоритми (Greedy).

Тема 14 от Конспекта

Алгоритъм на Дейкстра

Това е най-известният алгоритъм за намиране на най-кратък път от един начален връх до всички останали върхове в ориентиран или неориентиран граф с неотрицателни тегла на ребрата (напр. разстояние в километри).

Основна логика:

  1. Създаваме масив distance[], в който записваме разстоянието до всеки връх. Първоначално всички са Безкрайност (Infinity), а началният е 0.
  2. На всяка стъпка избираме непосетения връх с най-малко разстояние.
  3. Релаксация: Проверяваме съседите му. Ако пътят до съсед през текущия връх е по-къс от досега известния, го обновяваме.
  4. Маркираме върха като посетен.

C# Имплементация (с Матрица)

void Dijkstra(int[,] graph, int startNode, int verticesCount)
{
    int[] dist = new int[verticesCount];
    bool[] visited = new bool[verticesCount];

    // Инициализация с "безкрайност"
    for (int i = 0; i < verticesCount; i++)
    {
        dist[i] = int.MaxValue;
        visited[i] = false;
    }
    dist[startNode] = 0; // Разстоянието до себе си е 0

    for (int count = 0; count < verticesCount - 1; count++)
    {
        // Намираме непосетения връх с минимално разстояние
        int u = GetMinDistance(dist, visited, verticesCount);
        visited[u] = true;

        // Релаксация на съседите
        for (int v = 0; v < verticesCount; v++)
        {
            if (!visited[v] && graph[u, v] != 0 &&
                dist[u] != int.MaxValue &&
                dist[u] + graph[u, v] < dist[v])
            {
                dist[v] = dist[u] + graph[u, v];
            }
        }
    }
}
Тема 15 от Конспекта

Минимално покриващо дърво (MST)

Представи си, че трябва да прекараш оптичен интернет до няколко града. Искаш всички градове да са свързани помежду си, но търсиш минималната обща дължина на кабелите. Това се нарича Минимално покриващо дърво (Minimum Spanning Tree).

Лакоми алгоритми (Greedy Algorithms): Тези алгоритми правят локално най-добрия избор (вземат най-евтиното ребро) на всяка стъпка, надявайки се, че това ще доведе до глобален оптимум. При MST това работи перфектно!

Алгоритъм на Прим (Prim's Algorithm)

Много прилича на Дейкстра, но вместо да трупа общото разстояние от началото, той записва само цената на най-евтиното ребро, което свързва даден връх с вече изграденото дърво.

  1. Започваме от произволен връх.
  2. Намираме най-евтиното ребро, което свързва върха с непосетен съсед.
  3. Добавяме съседа към дървото и повтаряме, докато всички върхове не бъдат обхванати (без да създаваме цикли).
Тема 16 от Конспекта

Топологична сортировка

Използва се, когато имаме задачи със зависимости. Например: "Не можеш да си обуеш обувките, преди да си обул чорапите." За да работи, графът ЗАДЪЛЖИТЕЛНО трябва да бъде Ориентиран и Ацикличен (DAG - Directed Acyclic Graph).

Метод чрез DFS (по Светлин Наков)

Идеята е брилянтна: пускаме стандартно търсене в дълбочина (DFS). Когато даден връх приключи с обработката на всички свои наследници (т.е. напускаме рекурсията за него), го добавяме в Стек. Накрая вадим всичко от стека и получаваме правилния ред!

C# Реализация

void TopologicalSort(int v, bool[] visited, Stack<int> result, List<int>[] adj)
{
    visited[v] = true; // Маркираме текущия връх за посетен

    // Обхождаме всичките му наследници
    foreach (int neighbor in adj[v])
    {
        if (!visited[neighbor])
        {
            TopologicalSort(neighbor, visited, result, adj);
        }
    }

    // Напускаме рекурсията -> Задължително влиза в Стека!
    result.Push(v);
}

Забележка: Времевата сложност е линейна O(V + E), защото всеки връх и всяко ребро се обхождат точно веднъж.

Генерална репетиция

ВЪПРОС 1 — СЛАБОСТ НА ДЕЙКСТРА
Защо алгоритъмът на Дейкстра не работи правилно, ако в графа има ребра с отрицателни тегла (напр. -5)?
👆 Кликни за отговор
Дейкстра разчита на принципа на "лакомите алгоритми". Щом избере върха с най-малко моментно разстояние и го маркира като "посетен", алгоритъмът приема, че по-къс път до него никога няма да бъде намерен. Ако обаче по-нататък в графа има отрицателно ребро, то би могло да намали разстоянието до вече "финализиран" връх, но алгоритъмът никога няма да се върне да го поправи. За такива случаи се ползва алгоритъмът на Белман-Форд.
ВЪПРОС 2 — MST СРЕЩУ SHORTEST PATH
Каква е разликата между Минимално покриващо дърво (MST) и Дърво на най-кратките пътища (както го генерира Дейкстра)?
👆 Кликни за отговор
- MST (Прим/Крускал): Гарантира минималното общо тегло на всички ребра, нужни за свързването на ВСИЧКИ върхове (минимизира цената на цялата мрежа).

- Дейкстра: Гарантира, че разстоянието от един конкретен начален връх до който и да е друг е абсолютно минимално. Общата дължина на ребрата обаче може да не е най-евтината за цялата мрежа.
ВЪПРОС 3 — СРИВ В ТОПОЛОГИЯТА
Ако вмъкнем "цикъл" в графа (напр. Задача А изисква Б, Б изисква В, а В изисква А), какво ще се случи с топологичната сортировка?
👆 Кликни за отговор
Алгоритъмът ще се провали, защото зависимостите стават нерешими (Парадоксът на кокошката и яйцето). Топологична сортировка може да бъде генерирана единствено за DAG (Directed Acyclic Graph) - ориентиран граф БЕЗ цикли. Ако използваме метода със стека, резултатът просто ще бъде грешен/нелогичен, затова често в кода се добавя проверка за цикли преди изпълнението.
