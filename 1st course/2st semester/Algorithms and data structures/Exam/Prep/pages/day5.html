Алгоритми O(n log n)

Ден 5: Бързи алгоритми и Търсене

Докато сортировките от Ден 4 бяха лесни, но бавни (O(n²)), днес навлизаме в тежката артилерия. Алгоритмите тип „разделяй и владей“ (Divide and Conquer) са гръбнакът на съвременното програмиране, защото намаляват времето за изпълнение драстично.

🎯 Фокус за изпита: Проф. Голев много държи на разбирането за pivot (стопиращ елемент) при Quick Sort и защо най-лошият случай става O(n²). За Merge Sort трябва да знаеш как се използва помощният масив за сливането и че той е УСТОЙЧИВА сортировка.

Какво покриваме днес:

  • Тема 4: Бърза сортировка (Quick Sort). Разделяне (Partitioning) и рекурсия.
  • Тема 5 (Част 1): Двоично търсене (Binary Search). Как намираме елемент за O(log n).
  • Тема 5 (Част 2): Сортировка чрез сливане (Merge Sort). Сливане на два подмасива.
Тема 4 от Конспекта

Бърза сортировка (Quick Sort)

Това е най-популярният сортиращ алгоритъм в практиката. Работи на следния принцип:

  1. Избираме елемент x (pivot), в кода на професора това е средният елемент.
  2. Разделяне (Partitioning): Местим всички числа, по-малки от x, отляво, а по-големите – отдясно.
  3. Извикваме същия метод рекурсивно за лявата и за дясната половина.

C# Реализация (по проф. Голев)

static void QuickSort(int[] arr, int lb, int rb) 
{
    int i = lb, j = rb;
    int x = arr[(lb + rb) / 2]; // Pivot е средният елемент

    // 1. Разделяне на масива
    while (i <= j) 
    {
        while (i <= rb && arr[i] < x) i++;
        while (lb <= j && arr[j] > x) j--;
        
        if (i <= j) 
        {
            arr.SwapElements(i, j); // Размяна на елементи в грешната половина
            i++; 
            j--;
        }
    }

    // 2. Рекурсия за лявата и дясната част
    if (i < rb) QuickSort(arr, i, rb);
    if (lb < j) QuickSort(arr, lb, j);
}
Времева сложност: В най-добрия и средния случай сложността е O(n log n). Но ако масивът вече е сортиран и за пивот се избира винаги крайният елемент, сложността деградира до O(n²). В кода на проф. Голев се взима средният, което предпазва от този случай при сортирани масиви.

Устойчивост: НЕУСТОЙЧИВА. Разменя отдалечени елементи и нарушава реда на еднаквите стойности.
Тема 5 (Търсене)

Двоично търсене (Binary Search)

Ако масивът ВЕЧЕ Е СОРТИРАН, няма нужда да го обхождаме целия (с линейно време O(n)), за да намерим елемент. Можем да го "разцепваме" на две на всяка стъпка, постигайки изумителната сложност от O(log n).

C# Реализация за масив от низове (по проф. Голев)

Тук търсим дума в сортиран речник dict. CompareTo() връща 0 (ако са равни), -1 (по-малко) или 1 (по-голямо).

int FindWord(string str, string[] dict) 
{
    int l = 0; 
    int r = dict.Length - 1;
    int m, cmp;

    while (l <= r) 
    {
        m = (l + r) / 2; // Намираме средата
        cmp = str.CompareTo(dict[m]);
        
        if (cmp == 0) 
            return m; // Намерен! Връща индекса.
        else if (cmp < 0) 
            r = m - 1; // Търсим в лявата половина
        else 
            l = m + 1; // Търсим в дясната половина
    }
    return -1; // Не е намерен
}
Тема 5 (Сортиране)

Сортировка чрез сливане (Merge Sort)

Отново алгоритъм „разделяй и владей“. Той гарантирано разделя масива на две точни половини, докато не останат парчета от по 1 елемент. След това започва да ги слива в правилен ред.

За сливането задължително се изисква допълнителен масив (tmp_arr) в паметта!

C# Реализация (по проф. Голев)

static int[] tmp_arr; // Помощен масив с размера на оригиналния

// Основната рекурсивна функция
static void MergeSort(int[] arr, int left_i, int right_i) 
{
    int middle_i;
    if (left_i < right_i) 
    {
        middle_i = (left_i + right_i) / 2;
        MergeSort(arr, left_i, middle_i);       // Сортиране на лява част
        MergeSort(arr, middle_i + 1, right_i);  // Сортиране на дясна част
        MergeArr(arr, left_i, middle_i, right_i); // СЛИВАНЕ
    }
}

// Методът, който върши истинската работа по сливането
static void MergeArr(int[] arr, int left_i, int middle_i, int right_i) 
{
    int i = 0, j = left_i, k;
    
    // 1. Копираме лявата част във временния масив
    while (j <= middle_i) tmp_arr[i++] = arr[j++];

    i = 0; 
    j = middle_i + 1; 
    k = left_i;
    
    // 2. Сравняваме елементи от лявата (в tmp_arr) и дясната част
    while (k < j && j <= right_i) 
    {
        if (tmp_arr[i] <= arr[j]) arr[k++] = tmp_arr[i++];
        else arr[k++] = arr[j++];
    }
    
    // 3. Ако са останали елементи вляво, ги добавяме накрая
    while (k < j) arr[k++] = tmp_arr[i++];
}
Сложност: O(n log n) ВИНАГИ. Няма най-лош случай от O(n²). Дълбочината на дървото е log n, а на всяко ниво се сливат n елемента.

Устойчивост: УСТОЙЧИВА. При сливането (когато са равни tmp_arr[i] <= arr[j]), първо се взема елементът от лявата част, запазвайки оригиналния ред.
Проверка на знанията

Интерактивна тренировка

Сравни Quick Sort и Merge Sort с тези изпитни въпроси.

ВЪПРОС 1 — ИЗБОР НА АЛГОРИТЪМ
Трябва да сортирате масив от обекти Студент, първо по възраст, а след това по успех (така че студентите с еднакъв успех да останат подредени по възраст). Коя сортировка ще изберете – Quick Sort или Merge Sort, и защо?
👆 Кликни за отговор
Трябва да изберем Merge Sort (Сортировка чрез сливане).

Причината е, че задачата изисква запазване на предходен ред (когато стойностите са равни). Следователно ни трябва устойчива (stable) сортировка. Merge Sort е устойчива, докато Quick Sort не е.
ВЪПРОС 2 — НАЙ-ЛОШ СЛУЧАЙ ПРИ QUICK SORT
Как възниква най-лошият случай (O(n²)) при Бързата сортировка и каква е превенцията срещу него в кода на проф. Голев?
👆 Кликни за отговор
Най-лошият случай възниква, когато масивът се раздели максимално небалансирано на всяка стъпка (напр. пивотът се оказва най-малкият или най-големият елемент, което оставя една част празна, а другата с N-1 елемента). Това се случва най-често при вече сортиран масив, ако винаги се избира първият или последният елемент за пивот.

Превенцията: В кода на проф. Голев за пивот се избира средният елемент: x = arr[(lb + rb) / 2]. Това предотвратява O(n²) сценария при предварително сортиран масив.
ВЪПРОС 3 — ПАМЕТ
Каква е разликата в изискванията за памет между Quick Sort и Merge Sort?
👆 Кликни за отговор
- Quick Sort: Сортира in-place (на място). Изисква много малко допълнителна памет – само за рекурсивните извиквания в системния стек (O(log n)).

- Merge Sort: Не е in-place. Изисква заделяне на цял допълнителен помощен масив (tmp_arr) с размер O(n), за да може да извърши сливането на елементите. Това го прави по-тежък откъм памет.
